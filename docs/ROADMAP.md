# Ruruma roadmap

Dates depend on real demand and service access.
The roadmap does not promise delivery dates or active integrations.

## First release

The first release lets visitors explore services and industry examples.
Visitors can review founder work and prepare a project brief.
They can download the brief or open an email draft.
Optional device storage supports draft recovery and a clear action.
The release needs no account, database, payment provider, or AI API key.

The service model has three stages:

1. Define a workflow and its baseline.
2. Build a bounded pilot with review and cost limits.
3. Measure the pilot before a wider rollout.

Each engagement needs its own written scope and price.
The website does not sell a fixed subscription.

## Next: better enquiry intake

Add server intake only after the owner selects a provider and retention policy.
The intake must check input and limit abuse.
The intake must prevent duplicate records and protect private enquiries.
The intake must show accurate retry and delivery states.
Add calendar links only when the founder supplies an active calendar.

## Next: verified case studies

Add customer case studies only with customer permission.
Include the baseline, method, measurement period, and limits.
Distinguish a backtest from a result in production.
Add testimonials only when the quoted person approves the text and attribution.

## Later: client workspace

Add a client workspace only when actual projects need it.
Use authentication and authorization before any private records.
Isolate each client's records and files.
Define retention, deletion, backups, and audit access.

## Later: live AI tools

Add live AI demonstrations only after cost, safety, and data boundaries are clear.
Use explicit labels for synthetic examples.
Keep human review for consequential business actions.
Do not imply that every named integration is active.

## Domain and hosting

Connect `ruruma.me` after the owner confirms domain ownership and DNS access.
Use the approved free Sites host for this release.
Keep the static build portable to another suitable host.
Vercel activation needs a suitable commercial plan and restored team access.
